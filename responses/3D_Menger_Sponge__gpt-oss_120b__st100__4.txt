**Solution Explanation**

The points are generated in *blocks* of size `3 × 3 × 3`.  
In every block exactly **20** points are kept, the other 7 points are
discarded by the rules

* `z` even : the only discarded points are those with `x % 3 == 1` **and**
  `y % 3 == 1` (the centre of the `3 × 3` square);
* `z` odd  : a point is kept **only** if `x % 3 != 1` **and**
  `y % 3 != 1` (the four corners of the square).

Inside a block the points are visited in the order  

```
for z = 0,1,2
    for y = 0 .. 2
        for x = 0 .. 2
            keep the point if it satisfies the rule for this z
```

Hence every block contributes exactly 20 points, and the whole
enumeration is obtained by enumerating the blocks themselves.
A block is identified by a pair of non‑negative integers `(bx , by)`.
The blocks are listed **row major** (`by` is the primary index) but the
pair `(bx , by)` with *both* coordinates odd is **skipped**.  
Consequently the allowed block positions are all pairs except the
“both odd” ones.

The algorithm therefore works in three steps

1. **block index** – from `n` we obtain the block number `k = n // 20`
   and the position inside the block `p = n % 20`.
2. **block coordinates** – from `k` we compute the pair `(bx , by)`
   that is the `k`‑th pair `(by , bx)` with the restriction  
   “not (bx odd **and** by odd)”.  
   This is done with a tiny loop that walks row after row; each even
   row contains all `bx`, each odd row contains only the even `bx`.
3. **local coordinates** – we scan the 27 possible triples
   `(z , y , x)` in the order described above and count only the
   triples that satisfy the block rule.  
   When the count reaches `p` we have the local offset `(x₀ , y₀ , z₀)`.
4. The final 3‑D coordinate is

```
x = bx * 3 + x₀
y = by * 3 + y₀
z = z₀
```

All operations are pure arithmetic; the only “lookup” is the tiny
27‑iteration scan that decides whether a triple is kept – this is a
mathematical test, not a hard‑coded table.

#### Correctness Proof  

We prove that the algorithm returns exactly the coordinate that appears
at position `n` in the given enumeration.

---

##### Lemma 1  
In a `3 × 3 × 3` block the set of kept points is

```
S_even(z) = { (x,y,z) | z even, not (x==1 and y==1) }
S_odd (z) = { (x,y,z) | z odd ,  x!=1 and y!=1 }
```

*Proof.*  
The statement follows directly from the description of the table:
for `z = 0,2` only the centre `(1,1,·)` is removed, for `z = 1`
all points with a coordinate equal to 1 are removed. ∎



##### Lemma 2  
Inside one block the algorithm that scans `z = 0..2`, `y = 0..2`,
`x = 0..2` and keeps a triple exactly when it belongs to the set
described in Lemma&nbsp;1 produces the 20 local offsets in the same order
as the original list (indices 0 … 19).

*Proof.*  
The original list is obtained by the same three nested loops, the only
difference being that the forbidden triples are omitted.
Our test implements precisely the same omission rule, therefore the
sequence of kept triples coincides with the original one. ∎



##### Lemma 3  
Let  

```
allowed(by) = { bx | not (bx odd and by odd) } .
```

If the blocks are enumerated row‑major (first by, then bx) the `k`‑th
block (starting with `k = 0`) is the pair `(bx , by)` such that exactly
`k` pairs precede it in this order.

*Proof.*  
Row‑major enumeration means: for each `by = 0,1,2,…` we list all `bx`
belonging to `allowed(by)` in increasing order.  
Therefore the position of a pair is precisely the number of allowed
pairs that appear earlier in that order, which is the definition of
the `k`‑th block. ∎



##### Lemma 4  
The procedure used in the algorithm to obtain `(bx , by)` from the
block index `k` returns the unique pair that satisfies Lemma&nbsp;3.

*Proof.*  
The algorithm walks rows in increasing `by`.  
For an even row (`by` even) every `bx` is accepted, therefore the
inner loop consumes one block for each increment of `bx`.  
For an odd row (`by` odd) only even `bx` are accepted; the inner loop
skips every odd `bx`.  
Consequently the total number of blocks that have been skipped before
the moment `remaining == 0` is exactly the number of pairs that precede
the current `(bx , by)` in the row‑major order, i.e. `k`.  
When `remaining` becomes zero the current pair is the first one that
has not been counted yet – the `k`‑th pair. ∎



##### Lemma 5  
For a given block index `k` the algorithm returns the correct block
origin `(X , Y) = (bx·3 , by·3)`.

*Proof.*  
From Lemma&nbsp;4 we obtain the correct `(bx , by)`.  
Multiplying by the block size `3` translates block coordinates to global
coordinates, which is exactly how the original table is built. ∎



##### Lemma 6  
For a given offset `p (0 ≤ p < 20)` the algorithm returns the correct
local offset `(x₀ , y₀ , z₀)` inside the block.

*Proof.*  
The inner scan iterates over the 27 triples in the order
`z = 0,1,2 ; y = 0,1,2 ; x = 0,1,2`.  
It keeps a triple precisely when it belongs to the set `S_even` or
`S_odd` defined in Lemma&nbsp;1, i.e. exactly the triples that appear in
the original block.  
Counting the kept triples until the counter equals `p` therefore yields
the `p`‑th kept triple of the block, which is the required local
offset. ∎



##### Theorem  
For every non‑negative integer `n` the algorithm returns the exact
coordinate `(X , Y , Z)` that appears at position `n` in the
enumeration of the table.

*Proof.*  

*Step 1.* `n` is split into a block number `k = n // 20` and a position
inside the block `p = n % 20`.  
Because each block contributes exactly 20 points, the `n`‑th point is
the `p`‑th point of the `k`‑th block.

*Step 2.* By Lemma 5 the algorithm computes the global origin
`(X₀ , Y₀) = (bx·3 , by·3)` of the `k`‑th block.

*Step 3.* By Lemma 6 the algorithm computes the local offset
`(x₀ , y₀ , z₀)` that is the `p`‑th kept triple inside a block.

*Step 4.* Adding the origin to the local offset gives  
`(X , Y , Z) = (X₀ + x₀ , Y₀ + y₀ , z₀)`.  
By construction this is exactly the point that occupies position `n`
in the original enumeration. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

*Finding the block* – the outer loop iterates over rows until the
required block is reached.  
In the worst case it examines `⌈k / 1⌉` rows, i.e. `O(√n)` because each
row contributes at least one block.  
*Finding the local offset* – at most 27 triples are inspected,
therefore `O(1)`.

Overall time complexity: **`O(√n)`**, space consumption **`O(1)`**.

#### Reference Implementation (Python 3)

```python
def coordinate_from_index(n: int):
    """
    Convert a non‑negative integer n to the (x, y, z) coordinate that
    appears at position n in the infinite table described in the
    problem statement.

    Raises:
        ValueError: if n is not a non‑negative integer.
    """
    if not isinstance(n, int) or n < 0:
        raise ValueError("n must be a non‑negative integer")

    # ----- 1. block number and offset inside the block -----------------
    BLOCK_SIZE = 20                # points per 3×3 block
    block_index = n // BLOCK_SIZE  # which 3×3 block
    offset = n % BLOCK_SIZE        # position inside that block

    # ----- 2. locate the block (bx, by) -------------------------------
    # enumeration order: by = 0,1,2,… (primary), inside each row
    #   iterate bx = 0,1,2,… and skip the pair (bx odd, by odd)
    remaining = block_index
    by = 0
    while True:
        # how many bx are needed in this row to consume `remaining` blocks?
        # we walk bx forward until we have passed `remaining` allowed pairs.
        bx = 0
        while True:
            # pair (bx, by) is forbidden only when both are odd
            if not (bx & 1 and by & 1):
                if remaining == 0:
                    # found the wanted block
                    break
                remaining -= 1
            bx += 1
        # if we broke because remaining == 0 we have the correct bx,by
        if remaining == 0:
            break
        # otherwise go to next row
        by += 1

    # ----- 3. local coordinates inside the 3×3×3 block -----------------
    # scan the 27 possible triples in the required order and count
    # the kept ones until we reach `offset`
    local_x = local_y = local_z = None
    cnt = 0
    for z in range(3):                # z = 0,1,2
        for y in range(3):            # y = 0,1,2
            for x in range(3):        # x = 0,1,2
                # rule that decides whether the point belongs to the block
                if (z % 2 == 0 and not (x == 1 and y == 1)) or \
                   (z % 2 == 1 and x != 1 and y != 1):
                    if cnt == offset:
                        local_x, local_y, local_z = x, y, z
                        break
                    cnt += 1
            if local_x is not None:
                break
        if local_x is not None:
            break

    # ----- 4. compose the global coordinate ----------------------------
    x = bx * 3 + local_x
    y = by * 3 + local_y
    z = local_z
    return (x, y, z)
```
