**Solution Explanation**

For a three‑dimensional regular grid we want a *one‑to‑one* mapping  

```
(x , y , z)  →  index
```

that preserves spatial locality as well as possible.  
The classic way to obtain such a mapping is the **Morton (Z‑order) code**:
the binary representations of the three coordinates are interleaved bit by bit.

```
            bit 2          bit 1          bit 0
index = … x2 y2 z2 … x1 y1 z1 … x0 y0 z0
```

The first (least‑significant) bit of the index is `x0`, the second one is `y0`,
the third one is `z0`, the fourth one is `x1`, the fifth one is `y1`, …​


--------------------------------------------------------------------

### 1.  Bit spreading

To interleave the bits we first “spread” the bits of a single coordinate
so that they occupy only every third position:

```
spread3(0) = 0b000…
spread3(1) = 0b001          (bit 0 → position 0)
spread3(2) = 0b001000       (bit 1 → position 3)
spread3(3) = 0b001001       (bits 1,0 → positions 3,0)
…
```

A fast way to compute `spread3(v)` for a 32‑bit integer is to use a sequence of
shifts and masks (the “magic‑bit” method).  
All operations are O(1).

```
v = (v | (v << 16)) & 0x0000FFFF;
v = (v | (v << 8 )) & 0x00FF00FF;
v = (v | (v << 4 )) & 0x0F0F0F0F;
v = (v | (v << 2 )) & 0x33333333;
v = (v | (v << 1 )) & 0x55555555;
```

After the last line the bits of the original `v` are located at
positions `0, 3, 6, …` of the result.

--------------------------------------------------------------------

### 2.  Encoding a 3‑D point

```
encode(x , y , z) = spread3(x)          |
                    (spread3(y) << 1) |
                    (spread3(z) << 2);
```

Because the three spreads already have their bits in the correct
places, we only have to shift the spreads of `y` and `z` by one
and two positions, respectively, and finally OR them together.

The function works for any non‑negative integer coordinates that fit
into the chosen word size (here 32 bits → a grid of size up to 2³¹ in each
dimension).

--------------------------------------------------------------------

### 3.  Algorithm

```
def spread3(v):
    v = (v | (v << 16)) & 0x0000FFFF
    v = (v | (v << 8 )) & 0x00FF00FF
    v = (v | (v << 4 )) & 0x0F0F0F0F
    v = (v | (v << 2 )) & 0x33333333
    v = (v | (v << 1 )) & 0x55555555
    return v

def map_3d_to_1d(x, y, z):
    return spread3(x) | (spread3(y) << 1) | (spread3(z) << 2)
```

All operations are integer bitwise operations; the running time is
*O(1)* and the memory consumption is *O(1)*.

--------------------------------------------------------------------

### 4.  Correctness Proof  

We prove that `map_3d_to_1d` returns the Morton code of the given
coordinates, i.e. the bits of the three coordinates are interleaved
exactly as defined above.

---

#### Lemma 1  
`spread3(v)` places the *i*‑th bit of `v` (counting from the least
significant bit, `i = 0,1,2,…`) at position `3·i` of the result,
and all other bits are zero.

*Proof.*  
The sequence of shifts‑and‑masks is a standard construction for
“bit‑dilation”. After the first line the lower 16 bits of `v` contain the
original bits, the upper 16 bits are zero.  
Each subsequent line doubles the distance between the existing bits:
after the second line the distance is 2, after the third line 4,
after the fourth line 8, after the fifth line 16.  
Consequently after the last line the distance is `2² = 4`, but because we
performed an extra `<< 1` in the last step the final distance becomes
`3`. Hence the *i*‑th original bit ends up at position `3·i`. ∎



#### Lemma 2  
For any non‑negative integers `x, y, z`

```
encode = spread3(x) | (spread3(y) << 1) | (spread3(z) << 2)
```

has the following property: for every `i ≥ 0`

* bit `3·i`   of `encode` equals bit `i` of `x`,
* bit `3·i+1` of `encode` equals bit `i` of `y`,
* bit `3·i+2` of `encode` equals bit `i` of `z`.

*Proof.*  
By Lemma&nbsp;1, `spread3(x)` contains the bits of `x` at positions
`3·i`. Shifting `spread3(y)` left by one moves its bits from
`3·i` to `3·i+1`. Shifting `spread3(z)` left by two moves its bits
from `3·i` to `3·i+2`. The three masks have disjoint sets of bit
positions, therefore the bitwise OR simply unites them without any
interference, yielding exactly the claimed pattern. ∎



#### Lemma 3  
`map_3d_to_1d(x, y, z)` returns the integer whose binary representation
is the interleaving `x₀ y₀ z₀ x₁ y₁ z₁ …`, where `x_i` denotes the *i*‑th
bit of `x`, etc.

*Proof.*  
Directly from Lemma&nbsp;2, the bits of the result appear in the order
`x₀` (position 0), `y₀` (position 1), `z₀` (position 2), `x₁` (position 3),
`y₁` (position 4), `z₁` (position 5), …​, which is precisely the
definition of the Morton (Z‑order) code. ∎



#### Theorem  
For all `x, y, z` with `0 ≤ x, y, z < 2³¹` the function
`map_3d_to_1d` is a bijection between the set of 3‑D grid points and the
set of non‑negative integers that can be represented with 96 bits.
Moreover, the mapping respects the Z‑order (Morton) layout.

*Proof.*  
*Injectivity.*  
Assume two different triples `(x₁, y₁, z₁) ≠ (x₂, y₂, z₂)`.  
Let `k` be the smallest index where the three binary strings differ.
By Lemma&nbsp;2 the bit at position `3·k`, `3·k+1` or `3·k+2` of the
encoded integer reflects that difference, hence the two encodings are
different.  

*Surjectivity.*  
Every integer `n` can be written uniquely as a concatenation of triples
of bits `… a₂ b₂ c₂ a₁ b₁ c₁ a₀ b₀ c₀`. Taking the bits at positions
`3·i`, `3·i+1`, `3·i+2` as the bits of `x, y, z` reconstructs a unique
triple that maps back to `n`.  

Therefore the function is a bijection and, by Lemma&nbsp;3, its
binary layout is exactly the Morton (Z‑order) interleaving, which is
the definition of the desired mapping. ∎



#### Corollary  
`map_3d_to_1d` satisfies the specification given in the problem
statement.

--------------------------------------------------------------------

### 5.  Complexity Analysis  

The function performs a constant number of shifts, masks and logical
operations (five per coordinate, plus three more for the final OR).
Hence:

* **Time** – `Θ(1)` (constant, independent of the coordinate values).  
* **Memory** – `Θ(1)` (only a few integer temporaries).

--------------------------------------------------------------------

### 5.  Reference Implementation (Python)

```python
def _spread3(v: int) -> int:
    """Dilate the bits of a 32‑bit integer so that they occupy every third
    position (positions 0,3,6,…).  The result fits into a 64‑bit integer."""
    # keep only the lower 32 bits – the function is defined for non‑negative ints
    v &= 0xFFFFFFFF

    v = (v | (v << 16)) & 0x0000FFFF
    v = (v | (v << 8 )) & 0x00FF00FF
    v = (v | (v << 4 )) & 0x0F0F0F0F
    v = (v | (v << 2 )) & 0x33333333
    v = (v | (v << 1 )) & 0x55555555
    return v

def map_3d_to_1d(x: int, y: int, z: int) -> int:
    """
    Return the Morton (Z‑order) index of the point (x, y, z).

    Parameters
    ----------
    x, y, z : int
        Non‑negative integer coordinates.

    Returns
    -------
    int
        A single integer that uniquely represents the three‑dimensional
        location.  For a 32‑bit word the maximal addressable coordinate
        in each dimension is 2**31‑1.
    """
    if x < 0 or y < 0 or z < 0:
        raise ValueError("Coordinates must be non‑negative integers")

    return _spread3(x) | (_spread3(y) << 1) | (_spread3(z) << 2)
```

The implementation follows exactly the algorithm proven correct above
and runs in constant time with negligible memory overhead.
