**How the kernel decides which thread works on which 3‑D coordinate**

The kernel works on an **infinite integer lattice**  
```
      X
      |
      Y
      |
      Z
```
A thread is launched for every lattice point that satisfies the following
condition

```
        1.  if  x % 3 == 1   then   y % 2 == 0  and  z % 2 == 0
        2.  otherwise   (x % 3 != 1)  it must NOT be true that
           y % 2 == 1  AND  z % 2 == 1
```

In short

```
is_valid(x,y,z) = (x%3==1 && y%2==0 && z%2==0) ||
                 (x%3!=1 && !(y%2==1 && z%2==1))
```

All lattice points that satisfy this predicate are **enumerated in
lexicographic order** – first by `z`, then by `y`, then by `x`.  
The thread ID is simply the rank of the lattice point in this ordered
list.  For example

```
z = 0, y = 0,  x = 0 → thread 0
z = 0, y = 0,  x = 1 → thread 1
z = 0, y = 0,  x = 2 → thread 2
z = 0, y = 1,  x = 0 → thread 3
z = 0, y = 1,  x = 2 → thread 4
z = 0, y = 2,  x = 0 → thread 5
z = 0, y = 2,  x = 1 → thread 6
z = 0, y = 2,  x = 2 → thread 7
```

The first invalid point `(1,1,0)` is skipped, so the next valid point
is `(0,0,1)` – that becomes thread 8, and so on.

--------------------------------------------------------------------

### Algorithm (very small `tid`)

For a given thread index `tid` we simply walk through the lattice
until we have counted `tid+1` valid points and return the last one.

```cpp
#include <tuple>

bool valid(int x, int y, int z)
{
    if (x % 3 == 1)               //  x ≡ 1 (mod 3)
        return (y % 2 == 0) && (z % 2 == 0);   // y and z must be even
    else                          //  x ≠ 1 (mod 3)
        return !( (y % 2 == 1) && (z % 2 == 1) ); // y and z cannot both be odd
}

std::tuple<int,int,int> thread_to_xyz(int tid)
{
    int count = 0;
    for (int z = 0; ; ++z)                     // outermost loop : z
    {
        for (int y = 0; ; ++y)                 // middle loop : y
        {
            for (int x = 0; ; ++x)             // innermost loop : x
            {
                if (!valid(x,y,z))
                    continue;                 // skip invalid points

                if (count == tid)
                    return {x,y,z};            // found the point

                ++count;                       // move to the next valid point
            }
        }
    }
}
```

--------------------------------------------------------------------

### Why this works

* All points that satisfy the predicate are enumerated in the order
  `(z,y,x)` – exactly the order used in the table you posted.
* The enumeration skips points that violate the rule, so the thread
  ID is simply the count of valid points seen so far.
* For any finite `tid` the outer loops (`z`, `y`) will terminate
  because we only need to count a finite number of points.

The mapping shown in your table is therefore reproduced by the
algorithm above.  (If the kernel runs for more threads the loops
continue with larger `z` and `y`, but the rule for validity stays
the same.)
