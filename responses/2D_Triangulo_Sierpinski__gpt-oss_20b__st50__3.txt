**Solution Explanation**

For a pair of non‑negative integers `(x , y)` we write the numbers in binary

```
y : b_k … b_2 b_1 b_0          (b_i is 0 or 1)
x : a_k … a_2 a_1 a_0
```

`a_i ≤ b_i` for every position `i`.  
That means every bit that is set in `x` is also set in `y`, i.e.

```
x  is a submask of y            (x ⊆ y)
```

For a fixed `y` we can choose independently for every `1`‑bit of `y`
whether it is present in `x` or not.
If `y` has `cnt` one‑bits, then exactly

```
    2cnt
```

different `x` exist.  
The sequence in the statement is obtained by

```
for y = 0,1,2,3,4,…                    (increasing y)
    for x = 0,1,2,… ,y  with x ⊆ y     (increasing x)
        output (x , y)
```

The first terms are

```
(0,0)
(0,1) (1,1)
(0,2) (2,2)
(0,3) (1,3) (3,3)
(0,4) (4,4)
(0,5) (1,5) (5,5)
...
```

which is exactly the sequence given in the statement.



--------------------------------------------------------------------

#### 1.   Counting all pairs up to a given `y`

Let

```
S(y) = # { (x , k) | 0 ≤ x ≤ k ≤ y ,  x ⊆ k }
```

`S(y)` is the number of pairs printed **up to and including** the
last pair with the second component `y`.
For the algorithm we need

```
S(y-1) <  n   ≤  S(y)
```

so that the required pair has second component `y`.

--------------------------------------------------------------------

##### 1.1   Formula for `S(y)`

Scan the bits of `y` from most significant to least significant.
Let `p` be the number of one‑bits already seen.

```
result = 0
for every bit position i from high to low
        if y has a 1 at i
                result += 3^i          # all numbers < 2^i with this prefix
                p += 1

# finally all numbers having exactly the same prefix as y
result += 2^p
```

The justification:

* For a fixed most significant `1`‑bit at position `i` all
  numbers with a `0` there and any choice of the lower bits are already
  smaller than `y`.  
  The number of such numbers is `3^i` – every lower bit can be
  `0`, `1` or absent.
* After all higher bits are processed, the remaining numbers are the
  ones that have the same prefix as `y`.  
  Their number is exactly `2^p`, because every one‑bit of `y`
  may be chosen or not in `x`.

The loop needs at most `bit_length(y)` iterations  
(`≤ 60` for `y < 2^60`), therefore it is very fast.

--------------------------------------------------------------------

#### 2.   Binary search for the second component `y`

`S(y)` is strictly increasing with `y`.  
We find the smallest `y` with `S(y) > n` by binary search.

```
high = 1
while S(high) <= n :  high *= 2      # guarantee high is large enough

low = 0
while low < high :
        mid = (low + high)//2
        if S(mid) > n : high = mid
        else          : low  = mid + 1
y = low
```

`S(y-1)` (or `0` for `y = 0`) gives the number of printed pairs
before the block of `y`.  
`offset = n - S(y-1)` tells us the position inside the block of this
`y`.

--------------------------------------------------------------------

#### 3.   Reconstructing `x` from `offset`

All `x` with `x ⊆ y` are obtained by choosing independently for
every `1`‑bit of `y` whether it is present or not.

Let `pos[0 … cnt-1]` be the positions of the `1`‑bits of `y`
(increasing order).
For a binary representation of `offset`

```
offset = b0 b1 … b(cnt-1)   (b0 is the least significant bit)
```

the corresponding `x` is

```
x = Σ  bi * 2^pos[i]     (bi = 0 or 1)
```

`cnt` never exceeds the bit length of `y` (≤ 60), therefore the
operations are trivial.

--------------------------------------------------------------------

#### 4.   Correctness Proof  

We prove that the algorithm outputs the pair `(x , y)` that appears
at position `n` in the sequence described in the statement.

---

##### Lemma 1  
For a fixed `y` the number of integers `x` with `0 ≤ x ≤ y` and
`x ⊆ y` equals `2^{popcount(y)}`.

**Proof.**

Let `y` contain exactly `cnt` one‑bits.
For every such bit we may choose independently whether the same bit
is also set in `x` or not.
Thus there are `2` possibilities for each of the `cnt` bits,
hence `2^{cnt} = 2^{popcount(y)}` different `x`. ∎



##### Lemma 2  
For every integer `y ≥ 0`

```
S(y) = Σ_{i : y_i = 1} 3^i   +   2^{popcount(y)}
```

(where the sum runs over all bit positions `i` of `y`).

**Proof.**

All pairs `(x , k)` with `k < y` are already counted in `S(y-1)`.
The additional pairs that have the second component exactly `y`
are those described in Lemma&nbsp;1, therefore their number is
`2^{popcount(y)}`.

The remaining task is to compute `S(y-1)`.  
Consider the binary representation of `y` from most significant to
least significant bit.

* Whenever the current bit `i` of `y` equals `1`,
  all numbers `k < y` that have a `0` at this bit and
  arbitrary bits below it are already smaller than `y`.
  For each such lower part there are `3^i` possibilities
  (`0`, `1`, or absent for every lower bit).  
  Hence we add `3^i` to the count.
* Let `p` be the number of already seen `1`‑bits.
  After processing all bits, all numbers `k` with the *same* prefix as
  `y` and `k ≤ y` are exactly the numbers that can be obtained by
  choosing independently for those `p` positions whether the bit is
  present or not.  
  That is `2^p` possibilities.

Adding both parts yields the claimed formula. ∎



##### Lemma 3  
During the binary search the invariant  

```
S(low-1) ≤ n < S(high)
```

holds, and after the loop `y = low` satisfies  
`S(y-1) ≤ n < S(y)`.

**Proof.**

*Initialisation.*

`high` is increased until `S(high) > n`.  
`low` starts at `0`, thus `S(low-1) = 0 ≤ n` is true.

*Maintenance.*

If `S(mid) > n`, `high` becomes `mid`; otherwise `low` becomes
`mid+1`.  
In the first case the invariant stays true because `mid ≥ low`
and we only shrink the upper bound.  
In the second case `mid+1` is larger than `mid`, therefore
`S(low-1) = S(mid) ≤ n` and `S(high) > n` still hold.

*Termination.*

When `low = high`, the invariant gives `S(low-1) ≤ n < S(low)`,
hence the desired `y` is `low`. ∎



##### Lemma 4  
`offset = n – S(y-1)` satisfies `0 ≤ offset < 2^{popcount(y)}`.

**Proof.**

From Lemma&nbsp;3 we know `S(y-1) ≤ n < S(y)`.  
`S(y) – S(y-1)` equals the number of pairs with second component
`y`, which by Lemma&nbsp;1 is `2^{popcount(y)}`.
Therefore the difference `offset` is in the stated range. ∎



##### Lemma 5  
The procedure of Section&nbsp;3 reconstructs the unique `x`
with `x ⊆ y` whose position inside the block of `y` equals `offset`.

**Proof.**

Let `pos[0 … cnt-1]` be the positions of the one‑bits of `y`,
ordered increasingly.
For every bit `i` of `y` we decide independently
whether this bit is present in `x` or not.
If we write `offset` in binary, its least significant bit `b0`
determines the choice for the lowest position `pos[0]`,
`b1` for `pos[1]`, and so on.
Thus the mapping

```
x = Σ_{i}  bi * 2^{pos[i]}
```

produces exactly the `x` that corresponds to the binary
representation of `offset`.
Because there are `2^{cnt}` different combinations,
the reconstruction is bijective and the obtained `x`
belongs to the block of `y`. ∎



##### Theorem  
For the input integer `n` the algorithm outputs the pair
`(x , y)` that appears at position `n` (starting from `0`)
in the sequence described in the problem statement.

**Proof.**

By Lemma&nbsp;3 the algorithm finds `y` with
`S(y-1) ≤ n < S(y)`.  
Hence the pair at position `n` has second component `y`.

By Lemma&nbsp;4 the computed `offset` is the position
inside this block of `y`.

Lemma&nbsp;5 shows that the reconstruction step yields
the unique `x` with `x ⊆ y` that is in that position.

Therefore the algorithm outputs exactly the pair that occupies
position `n` in the sequence. ∎



--------------------------------------------------------------------

#### 5.   Complexity Analysis

Let `L` be the bit length of `y` (at most `60` for typical
problem limits, larger is harmless because Python integers are
arbitrary precision).

```
Binary search:      O(log n)  iterations
   each iteration: O(L) time for S(mid)
Reconstruction:     O(L) time
Total:              O(L * log n)    (≤ a few thousand operations)
Memory usage:       O(1)   (apart from the pre‑computed powers of 3)
```

--------------------------------------------------------------------

#### 6.   Reference Implementation  (Python 3)

```python
import sys

# -------------------------------------------------------------

def solve() -> None:
    data = sys.stdin.readline().strip()
    if not data:
        return
    n = int(data)

    # powers of 3 up to 64 (enough for y < 2^64)
    pow3 = [1]
    for _ in range(1, 65):
        pow3.append(pow3[-1] * 3)

    # S(y) = number of pairs with second component <= y
    def S(y: int) -> int:
        if y < 0:
            return 0
        res = 0
        cnt = 0                 # number of 1-bits already seen
        bl = y.bit_length()
        for i in range(bl - 1, -1, -1):
            if (y >> i) & 1:
                res += pow3[i]
                cnt += 1
        res += 1 << cnt
        return res

    # ---------- find y ----------
    low, high = 0, 1
    while S(high) <= n:        # guarantee high is large enough
        high <<= 1

    while low < high:
        mid = (low + high) // 2
        if S(mid) > n:
            high = mid
        else:
            low = mid + 1
    y = low

    # ---------- offset inside block ----------
    prev = S(y - 1) if y > 0 else 0
    offset = n - prev

    # ---------- reconstruct x ----------
    positions = []
    for i in range(y.bit_length()):
        if (y >> i) & 1:
            positions.append(i)

    x = 0
    for idx, pos in enumerate(positions):
        if (offset >> idx) & 1:
            x += 1 << pos

    print(f"{x} {y}")

# -------------------------------------------------------------
if __name__ == "__main__":
    solve()
```

The program follows exactly the algorithm proven correct above
and conforms to the required input / output format.
