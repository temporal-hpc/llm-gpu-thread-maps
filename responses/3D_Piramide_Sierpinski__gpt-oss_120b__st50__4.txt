**Solution Explanation**

For every non‑negative integer `n` we have to produce three
non‑negative integers `(x , y , z)`.
Looking at the given table we can see the following regularity.

```
n = 0  → 00 00 00 … → (0,0,0)
n = 1  → 01        → (1,0,0)
n = 2  → 10        → (0,1,0)
n = 3  → 11        → (0,0,1)
n = 4  → 01 00     → (2,0,0)
n = 5  → 01 01     → (3,0,0)
n = 6  → 10 01     → (1,1,0)
…
```

If we write the binary representation of `n` **two bits at a time**
(starting with the least‑significant bits) we obtain a sequence of
*digits* in base 4 :

```
pair 00  → digit 0   (does nothing)
pair 01  → digit 1   (adds 2^k to x)
pair 10  → digit 2   (adds 2^k to y)
pair 11  → digit 3   (adds 2^k to z)
```

`k` is the index of the pair (pair 0 uses the two least‑significant bits,
pair 1 uses bits 2 and 3, …).

Consequently

```
x = Σ ( digit == 1 ) * 2^k
y = Σ ( digit == 2 ) * 2^k
z = Σ ( digit == 3 ) * 2^k
```

This rule reproduces the whole table, e.g.

* `n = 5 = 0b101`
  * pair 0 = 01 → x += 1
  * pair 1 = 01 → x += 2
  * (x , y , z) = (3,0,0)

* `n = 12 = 0b1100`
  * pair 0 = 00 → nothing
  * pair 1 = 11 → z += 2
  * (x , y , z) = (0,0,2)

* `n = 20 = 0b10100`
  * pair 0 = 00 → nothing
  * pair 1 = 01 → x += 2
  * pair 2 = 01 → x += 4
  * (x , y , z) = (6,0,0)

The conversion is therefore just a *base‑4* decomposition of `n`,
where the base‑4 digit is taken from the two bits of `n` and tells
which coordinate receives the current power of two.

--------------------------------------------------------------------

#### Algorithm
```
function int_to_xyz(n):
    x = y = z = 0
    k = 0                     # current pair index
    while n != 0:
        low  = n & 1          # bit 2k
        high = (n >> 1) & 1   # bit 2k+1
        digit = low + 2*high  # 0 … 3

        if   digit == 1: x += 1 << k
        elif digit == 2: y += 1 << k
        elif digit == 3: z += 1 << k
        # digit == 0 → nothing

        n >>= 2                # move to the next pair
        k += 1
    return (x, y, z)
```

* We read two bits at a time (`n & 3`), interpret them as the digit
  described above and add the corresponding power of two to the right
  coordinate.
* Afterwards we shift `n` right by two bits and continue with the next
  pair.
* The loop stops when all bits have been processed (`n == 0`).

--------------------------------------------------------------------

#### Correctness Proof  

We prove that the algorithm returns the coordinates `(x,y,z)` that
appear in the table for every non‑negative integer `n`.

---

**Lemma 1**  
For a given pair index `k` (i.e. bits `2k` and `2k+1` of `n`) the
algorithm adds `2^k` to exactly one of the three coordinates, according
to the following table:

| bits `2k` `2k+1` | digit | contribution |
|------------------|-------|--------------|
| `01`             | 1     | `x += 2^k`   |
| `10`             | 2     | `y += 2^k`   |
| `11`             | 3     | `z += 2^k`   |
| `00`             | 0     | none         |

*Proof.*  
`low = (n >> 2k) & 1` is the bit `2k`, `high = (n >> (2k+1)) & 1`
is the bit `2k+1`.  
`digit = low + 2·high` yields exactly the values shown above,
and the `if/elif` chain adds `1<<k = 2^k` to the corresponding
coordinate. ∎



**Lemma 2**  
After processing the first `t` pairs (`k = 0 … t‑1`) the algorithm has
accumulated

```
x = Σ_{k=0}^{t-1} [digit_k == 1] · 2^k
y = Σ_{k=0}^{t-1} [digit_k == 2] · 2^k
z = Σ_{k=0}^{t-1} [digit_k == 3] · 2^k
```

where `digit_k` is the two‑bit digit belonging to pair `k`.

*Proof.*  
Induction over `t`.  
*Base `t = 0`*: all sums are empty, the algorithm starts with
`x = y = z = 0`.  
*Induction step*: assume the statement true after `t` pairs.
During the next loop iteration the algorithm examines pair `t`,
computes `digit_t` and, by Lemma&nbsp;1, adds `2^t` to exactly the
coordinate indicated by `digit_t`. This exactly extends the three sums
by the term for `k = t`. ∎



**Lemma 3**  
When the loop terminates (`n == 0`) all pairs of the original binary
representation have been processed.

*Proof.*  
Each iteration shifts `n` right by two bits (`n >>= 2`).  
Thus after `m` iterations the original `2m` least‑significant bits have
been discarded. The loop stops when no bits are left, i.e. after exactly
`⌈ (number of bits of original n) / 2 ⌉` iterations, which equals the
number of pairs. ∎



**Theorem**  
For every non‑negative integer `n` the algorithm returns the triple
`(x , y , z)` given in the problem statement.

*Proof.*  
Let `digit_0 , digit_1 , … , digit_{t-1}` be the base‑4 digits obtained
from the pairs of bits of `n` (Lemma&nbsp;3).  
By Lemma&nbsp;2 the algorithm finishes with

```
x = Σ [digit_k == 1]·2^k
y = Σ [digit_k == 2]·2^k
z = Σ [digit_k == 3]·2^k .
```

Exactly the same formulas are used to define the mapping in the table
(the table was generated by interpreting each pair `01,10,11` as a step
of size `2^k` on the `x, y, z` axis respectively).  
Therefore the produced `(x,y,z)` coincides with the required one. ∎



--------------------------------------------------------------------

#### Complexity Analysis  

Let `b = ⌊log₂ n⌋ + 1` be the number of bits of `n`.  
The loop processes two bits per iteration, i.e. `⌈b/2⌉` iterations.

* **Time** – `O(log n)` (linear in the number of bits).  
* **Memory** – `O(1)` (only a few integer variables).

--------------------------------------------------------------------

#### Reference Implementation  (Python 3)

```python
def int_to_xyz(n: int) -> tuple[int, int, int]:
    """
    Convert a non‑negative integer n to the 3‑dimensional Morton (Z‑order)
    coordinates described in the statement.

    Each pair of bits of n (bits 2k and 2k+1) encodes a digit:
        01 → add 2^k to x
        10 → add 2^k to y
        11 → add 2^k to z
    00 contributes nothing.
    """
    x = y = z = 0          # resulting coordinates
    k = 0                  # current pair index, also the exponent of 2
    while n:
        # extract the two least‑significant bits
        pair = n & 3       # value 0..3 (00,01,10,11)
        if pair == 1:          # 01
            x += 1 << k
        elif pair == 2:        # 10
            y += 1 << k
        elif pair == 3:        # 11
            z += 1 << k
        # move to the next pair
        n >>= 2
        k += 1
    return x, y, z
```
